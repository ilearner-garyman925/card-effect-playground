# 動態角色遊戲卡

把角色、背景、動作和卡面外殼分離，讓同一角色可以換背景、同一背景可以配不同角色。優先沿用使用者已接受的動作品質和外觀，不因換人而重新設計卡牌。

## 已確認的基準

本 skill 的 `assets/approved-card/` 是使用者確認合格版本的完整本機快照：黑銀金屬框、青藍紫箔光、電路紋卡背；hover 傾斜、高光跟隨游標、點擊及 Enter 翻面。卡內角色以六秒循環看平板、望向載具、返回正面，腳底固定，上半身擺動。

這是 **B.jpg 角色的參考實作，不是通用換裝引擎**。`acting.js` 的人物位置、頸肩軸心、頭部圖集範圍及載具裁切都是角色／場景專用。換資產前先讀 [基準與限制](references/baseline.md)。新角色不一定持平板，也不一定適合這段動作。

## 工作流程

**新增角色的預設流程是共用衣著、替換頭頸與前後髮。** 衣領、肩甲、身體、手臂與道具沿用同一份已接受的衣著素材；不得為每位角色重新生成一套外觀相似的服裝，再稱為共用。新增角色或處理頸肩／頭髮遮擋前，必讀 [共用衣著與頭髮分層](references/shared-outfits.md)。只有使用者要求新衣著或不同身體時，才新增相應衣著版本。新增帶法術的衣著時，依該參考的「已確認的仙俠服與獨立特效」拆開衣料、乾淨背景及可獨立啟閉的特效，並執行其 QC。

1. **判斷本次改動範圍**：新角色、換背景、換動作、修改卡面。已有資產先列出並看圖，不因缺少某個欄位便全部重生。
2. **建立身份包並接上共用衣著**：先以靜態原型確認臉、髮型、頭部比例及朝向，再製作頭頸、後髮、前髮並校準衣著接點。原型確認與拆件接入後的確認分開記錄。服裝和身體的拆件只在衣著包處理一次。其他動作拆件見 [角色工序](references/production.md)。原圖、生成版本和已接受版本分開保存。
3. **選背景包**：先按畫風、透視、站位及光源篩選，再按角色題材配對。閱讀 [資產規格與匹配](references/library.md)。在現有背景庫中提供有依據的候選，不默認每個角色都生成新背景。
4. **組合卡片配方**：身份 ID＋衣著 ID＋背景 ID＋特效 ID＋紋理 ID＋動作 ID＋卡框主題。各自獨立引用版本；人物持有道具歸衣著包，場景道具歸背景包，環境特效獨立配置。渲染程式未支援 manifest 時，先做可驗證的接入，不能把寫了 JSON 說成已具備置換功能。
5. **動畫和卡面分開驗收**：先在純色／棋盤底檢查人物，再合成背景，最後疊加箔光與翻面。依 [驗收清單](references/production.md#驗收) 及 [共用身份跨衣著 QC](references/shared-outfits.md#共用身份跨衣著-qc) 檢查實際畫面；不要只憑程式通過語法檢查便宣稱合格。

## 執行方式

- 一般圖像生成、去背或補畫使用環境提供的 imagegen 工具和 imagegen skill。先確認可用能力，不聲稱用了工具未回報的模型版本。純網頁的網格、關節及光效由程式處理。
- 不需要影片生成 API 或金鑰來播放本 skill 的網頁動畫。若使用者另行要求生成影片，先展示完整提示詞與起始圖供批准；影片的批准流程不額外套用到每次 CSS 或關節參數修改。
- 新任務可以先複製基準到 **新的目錄**：`node <skill>/scripts/create-prototype.mjs <absolute-destination>`。腳本拒絕覆寫已有目錄。它複製的是已驗證示範，並不會自動換人。
- 在既有專案修改時，只更動本次需要的檔案。保留已合格頁面或快照；不要讓新角色實驗破壞其他角色。
- 新的材質主題遵從使用者指定。沿用基準時，卡內人物動畫與外層 CSS 3D 翻面是兩套獨立動畫；箔光放在獨立覆蓋層，不能把整個人物提亮至失去細節。
- 本機預覽用 HTTP 提供 HTML/JS/CSS/圖片的正確 MIME。需要交付網站時遵循可用的網站工作流程；本 skill 本身不授權上傳或公開角色素材。

## 交付

提供可直接看的預覽、角色／背景所用版本、完成的互動及實際驗證結果。清楚區分：獨立分層、網格變形、姿勢替換／混合、真正連續臉部變形。標記原型尚存的問題，不把頭部交叉淡化稱為連續轉頭。
